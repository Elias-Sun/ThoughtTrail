# 评测说明与结果

> **结论先行**：本文是**开发集**上的离线评测。数据由开发者自拟（问题与相关证据）或按规则从源文本生成（复核、边界、记忆、自测），标注状态为 `draft_unreviewed`，未经独立人工复核；检索的向量路与重排使用确定性离线代理（词袋哈希向量、词项覆盖重排），复核与评分使用启发式基线。**这些结果用于验证评测管线与发现问题，不能作为第 9 节验收结论。**

## 2. 方法

- 检索参数冻结为 5.4 初始值：两路各 50、融合后 20 进入重排、最终 8 个核心证据单元；切块 1200/320；RRF k=60。
- Recall@K、nDCG@K、Precision/Recall 的计算方式见 [Presentation.md](Presentation.md#4-指标怎么算)；每项指标报告分子与分母。
- 消融：BM25、向量、混合、混合+重排、混合+重排但无父块扩展。
- `--live` 模式额外运行真实 `text-embedding-v4` + `qwen3-rerank` 检索与模型裁判复核（需要密钥，会产生费用）。

复现：

```bash
Scripts/eval.sh            # 离线
Scripts/eval.sh --live     # 追加真实模型（需 DASHSCOPE_API_KEY）
```

## 4. 解读与后续

1. **开发集偏容易，数值不能外推**。语料章节很短（每章 3 段，约 100–150 字），一个父块（以至一个子块）往往覆盖整章，所以 Recall@10 基本衡量的是“章节级定位”，扩展与否也看不出差别。验收集需要更长的章节，以及与证据只部分重叠的提问。
2. **复核集是规则扰动生成的**，启发式在改进后达到 100%，这只说明这些扰动类型都能被识别，不代表对真实模型回答的复核效果。第 9 节要求“不能只依赖生成答案的同一模型自评”，需要人工标注的陈述—证据对与模型裁判（`--live`）的对比结果。
3. **BM25 的跨书召回明显偏低（0.58）**：词法召回集中在词项最匹配的一本书上，另一本书的证据排在前 10 之外；加入向量路后跨书召回为 1.0（尽管是词袋代理）。这支持“完整策略的 Recall@10 不低于最佳单路”的设计，需用真实向量复核。
4. **待办（按第 9 节）**：建立更长章节的 12 本语料与人工标注的冻结验收集；用 `tt-bench eval --live` 运行真实 `text-embedding-v4`、`qwen3-rerank` 与模型裁判；补充回答依据（覆盖率/支持率）与不可回答识别率——这两项需要真实生成模型，离线无法评测；记录调用次数、Token 与费用（按服务端返回用量）。
5. 调参记录：本轮只做了一次改动（复核器数字归一化），初始结果 `173753Z` 与最终结果 `174510Z` 分开保存。
