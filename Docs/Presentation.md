# 项目讲解材料

## 1. 一句话

思迹把“读到哪里、想到什么、问了什么、记住了什么”串成一条可追溯的链：每个回答都标出依据来自原文、批注、个人反思还是长期记忆，并单独说明是否经过核查；新检索默认过滤未读内容；历史会话快照不保证逐轮重新校验来源与范围。

## 2. 为什么这样设计

| 问题 | 设计 | 对应代码 |
|---|---|---|
| 模型可能借检索结果剧透未读内容 | 以**文本区间**定义已读（不是页码/百分比）；召回时过滤、父块扩展时裁剪、提交前再检查、复核时结构检查四层防御；全书范围必须用户显式切换并记录 | `AccessScope`、`HybridRetriever`、`SmallToBig`、`StructuralChecker` |
| 模型可能放开限制（“读取其他书籍”） | 模型只提出语义计划，`PolicyCompiler` 裁决书籍、范围、来源、查询与预算；原文与笔记放在数据分隔块中并转义伪造标签 | `ContextRouting`、`PromptComposer` |
| 引用格式正确不代表内容被支持 | 拆分关键陈述 → 结构检查 → 语义裁判（模型或启发式基线）；失败/超时显示“未能核查”，不显示“已核查”；至多一轮修正 | `EvidenceVerificationCore` |
| 长期记忆被模型悄悄改写 | 模型只能提出候选；校验来源、重复、冲突；用户确认才写入；修改必须基于当前版本（冲突不静默覆盖）；修订留痕 | `BrainService`、`ProposalValidator` |
| 多组件重试导致请求数失控 | 每个任务一个共享预算：规划、查询向量、重排、生成、复核、修正、重试都计数；超限以明确状态结束 | `TaskBudget`、`BoundedExecutor` |
| 取消与完成竞争、重复点击 | 请求键 + 任务登记 + 完成门 + 数据库唯一键；取消立即持久化、迟到结果被丢弃 | `CompletionGate`、`TaskRegistry` |
| 中文检索 | FTS5 默认分词不适合中文：预分词为单字 + 二元组；BM25 与向量用 RRF 按名次融合 | `TextSegmenter`、`SQLiteRetrievalStore` |
| 离线与费用 | 本地词法索引覆盖全书结构；云向量只对已读范围增量生成并按内容指纹复用；需要在线模型的操作显示待处理或不可用 | `BookIndexer`、`OfflinePolicy` |

## 3. 失败怎样处理

| 故障 | 用户看到 | 数据 |
|---|---|---|
| 断网 / 超时 / 5xx / 限流 | 消息状态“失败”，提示原因，“重试”按钮 | 问题与草稿已保存；重试计入新预算 |
| 401 / 403 | “密钥无效 / 没有权限”，指向设置 | 不重试 |
| 流式中断 | “回答在传输中被截断” | 草稿保留，不标记成功 |
| 规划输出畸形 | 无感（规则策略接管），执行记录写明降级原因 | — |
| Embedding 不可用 / Rerank 失败 | 无感，执行记录写明降级 | 词法检索 / 保留融合排序 |
| 复核超时 / 解析失败 | “未能核查” | 回答与引用可查看 |
| 用户取消 | 立即“已取消”，草稿保留 | 迟到结果不会改写 |
| 进程被杀 | 下次启动：会话结束、任务标记中断、进行中回答标记失败 | 均可重试 |
| 备份损坏 / 校验和不符 | 明确错误，现有数据不变 | 恢复在单个事务中进行 |
| 麦克风/识别权限被拒、来电中断、无语音 | 明确提示，可继续文字输入 | 已录音频保留 |
| 磁盘写入失败（导入） | 导入失败提示 | 清理已写文件，无半成品书籍 |

## 4. 开发评测指标怎么算（当前验收不要求量化阈值）

- **Recall@K**：每个可回答问题，计算“被前 K 个结果命中的标注证据数 / 标注证据总数”，再对问题求平均；命中要求同书同章且重叠至少覆盖标注区间的 30%（或结果完全落在标注区间内）。
- **nDCG@K**：增益 2^grade − 1，每条标注证据只计一次。
- **复核 Precision/Recall**：把“矛盾、证据不足”视为需处理类别；“无法判断”的问题样本计入未检出，不删除难例。
- **边界违规**：任何检索/扩展单元超出该书已读区间即计 1 次违规，目标 0。
- 每项指标在报告中同时给出分子与分母、样本数、配置哈希、数据集哈希与代表性失败样本。

## 5. 演示路线（13.2）

验收可用现场操作记录或截图加步骤说明，不强制录像。以下确定性模式用于展示交互；本路线为可选展示；若声称真实 AI 效果，应有实际输出和人工核对，可使用 12 项可选案例。

1. 书库导入《阅读之道》（或任意 EPUB），打开阅读，选中段落做高亮与批注。
2. 菜单“记录反思”，文字或录音；反思页显示当时的书、章节与选段。
3. 选中段落点“提问”：回答流式出现 → “核查中” → “已核查”；点 E1 引用回到原文。
4. 提问时包含“错误示例”（演示模式）可得到数字被改写的回答，状态为“存在未获支持的陈述”，核查明细显示“存在矛盾”。
5. 问未读章节的内容：回答说明“在已读范围内没有找到依据”；切换“范围：全书”需确认，回答标记“全书范围”。
6. 回答下“提出记忆建议”→ 确认；在“思考与记忆”中修订并查看修订历史与来源（点击来源回到原文）。
7. “自测与复习”为本书出题 → 作答 → 反馈与证据 → 下次复习日期。
8. 问题包含“慢”时点“取消”，状态立即为“已取消”，可重试；问题包含“断网”时显示失败并保留问题；杀掉进程重开，数据仍在。
9. 设置中导出结构化备份 → 删除书籍 → 恢复备份，批注与引用关系仍在。

（第 4、8 步的关键词触发只存在于 `-demo` 确定性模式，真实模型下由真实故障触发。）

## 6. 仍有哪些限制

见 [Acceptance.md](Acceptance.md) 的“已知限制与可选改进”。最重要的三条：
1. 三类真实接口联调已通过（[live-check 报告](reports/live-check-2026-10-18T020716Z.md)）；真机验收 D-02～D-14 大部分已完成（自动化 + 用户手工，见 DeviceAcceptance）；当前已按调整后的个人项目范围完成；12 个真实案例检查与完整演示汇总均为可选；大规模量化评测与录像为可选；iOS 18 验收要求已取消；
2. 已确认采用纯文本阅读器，不要求 Readium、原书复杂排版与图片；语音承诺范围为中文，英文不纳入验收；
3. 系统支持与验收范围为 iOS 27；已有 iOS 27.0 模拟器和 iOS 27.0.1 真机测试记录。2026-10-18 用户取消 iOS 18 要求，旧版本报告作为历史证据保留。
